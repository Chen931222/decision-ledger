# 整理日：2026-11-14（clean-room.sh --contest 產出，摘要）

硬限制：一個人、約 5 週（12/4 前另有一場比賽）、Atlassian Forge 免費開發站、不花錢、台灣大學生、沒有真實企業客戶。

1. Agent Spend for Jira：每張 issue 記下 AI coding agent 為它花的 token 與錢，超預算時 agent 要先問人。本機 hook → Forge webtrigger → Forge SQL → 自訂欄位、儀表板、MCP 預算工具 check_budget、Rovo agent。瞄準 MCP＋Best Agents 加碼。風險：評審要在自己電腦裝 hook 才能測；只支援 Claude Code。
2. Provenance Check for Bitbucket：PR 標出哪幾行是 AI 寫的、人改過哪些，AI 比例過高時 merge 前要指定的人簽核。寫入當下 hook 留指紋 → Forge 比對 diff → merge check → 開 Jira 審查單。風險：小改就對不上；沒裝 hook 就繞過。
3. Decision Ledger for Jira：會議與留言中拍板的決定登記成雜湊鏈紀錄，有取代關係；新單違反仍有效的決定時，Rovo agent 附出處提醒。接 Teamwork Graph。風險：評審說 Rovo 本來就能搜；要先種有歷史的假專案。
4. Twin Pages for Confluence：中英對照頁，原文段落改了，譯文對應段落自動標過期，Rovo 依詞彙表擬更新稿等人核可。風險：ADF 沒有穩定段落 ID；被當成「又一個翻譯 app」。
5. Witness for Confluence：研究室實驗紀錄簽名鎖定、第二人見證、原始數據檔記指紋，日後能證明當天就存在且沒被改。Specialized Industries。風險：評審問頁面歷史不就有了；不能宣稱符合法規；Object Storage 免費站可能不能用。
6. Flake Ledger for Bitbucket：記住每個測試幾百次 pipeline 的成敗，紅燈時判斷是 flaky 還是真壞，自動開關 Jira 單、merge check。風險：Trunk、BuildPulse 已有類似；要自架 runner 累積歷史。
